# Мини-МИС — воркшоп «Разработка с ИИ-агентом по спецификации»

За 90 минут вы с ИИ-агентом добавите в учебную «Мини-МИС» работающий модуль: сначала спецификация, потом код, тесты и документация.

> **Только синтетические данные.** Не вводите реальные ФИО, адреса, СНИЛС или диагнозы — ни в форму, ни в агента.

## 1. Установка (10 минут)

1. **Node LTS** версии 20.19 или новее: https://nodejs.org (если нет интернета — с флешки ведущего).
2. **OpenCode и OpenSpec** — одна команда в терминале:
   ```
   npm i -g opencode-ai @fission-ai/openspec
   ```
3. **Файл настроек.** Скачайте `opencode.json` по QR-коду со слайда и положите в эту папку, рядом с `README.md`.
4. **Самопроверка:**
   ```
   npm run doctor
   ```
   Все пункты ✅ — запускайте агента в этой папке: `opencode`.

| Если видите | Сделайте |
|---|---|
| Windows: `running scripts is disabled on this system` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или откройте `cmd` вместо PowerShell |
| `opencode` / `openspec` не найден сразу после установки | Закройте и снова откройте терминал |
| macOS: `EACCES` при `npm i -g` | Та же команда с `sudo` в начале |
| Агент не знает команду `/opsx-propose` | Запускайте `opencode` из этой папки |
| Модель отвечает медленно | В opencode: `/models` → другой провайдер |

Не получается за 5 минут — садитесь в пару к соседу, это нормально.

## 2. Задача

> Поликлиника принимает заявки на вызов врача на дом. Форма: ФИО (синтетическое), участок (выпадающий список 1–5), время заявки, жалобы флажками. Если отмечен флажок «боль в груди», «потеря сознания», «затруднённое дыхание» или «судороги», заявка не регистрируется и показывается «Вызовите скорую помощь: 103». Иначе заявка до 14:00 обслуживается сегодня, с 14:00 — завтра. Результат — карточка вызова с датой визита.

Запуск приложения: `npm start` → http://localhost:3000. Пока модуль не сделан, вкладка серая.

## 3. Ход работы

| Этап | Что делаем | Команда в OpenCode |
|---|---|---|
| 0 | Агент знакомится с проектом | «Расскажи, что это за проект и как его запустить» |
| 1 | Обсуждаем задачу | `/opsx-explore` + текст задачи |
| 2 | Предложение и спецификация | `/opsx-propose add-home-visit-request` |
| 3 | **Читаем** `openspec/changes/add-home-visit-request/` и правим руками | `openspec validate add-home-visit-request` |
| 4 | Реализация, тесты | `/opsx-apply` → `npm test` → вкладка ожила |
| 5 | Проверка ведущего | `npm run test:tz` (тест выдаст ведущий) |
| 6 | Архив: спецификация уходит в `openspec/specs/` | `/opsx-archive` |
| ★ | Бонус: выходные, вкладки «ИМТ» и «Напоминания» | `/opsx-propose …` |

В Claude Code те же команды пишутся через двоеточие (`/opsx:propose`), в Codex — `$openspec-propose`.

## 4. Отстали — догоните

```
npm run catchup -- 2
```

Переход на этап группы. Ваши незакоммиченные изменения сохраняются в `git stash`, файл `opencode.json` не трогается. Список этапов: `npm run catchup`.

## 5. Полезные фразы для агента

- «Объясни этот код построчно, как студенту».
- «Тест упал, вот вывод: … Найди причину. Тесты не меняй».
- «Сначала напиши тест, который воспроизводит ошибку, потом исправь код».
- «Что ты сейчас сделал и почему?»
- Агент ушёл не туда — `Esc`, затем: «Откати последние изменения и предложи другой подход».
