# Design

## Context

Оболочка `index.html` подключает модуль `src/<id>.ui.js` и вызывает `mount(container)`. Логику держим отдельно от DOM, чтобы проверять её тестами `node:test`.

## Goals / Non-Goals

**Goals:**
- Чистая функция `createHomeVisit(request)` с предсказуемым результатом для каждого сценария спецификации.
- Простая форма во вкладке, результат — карточка.

**Non-Goals:**
- Хранение заявок, список вызовов, назначение конкретного врача.
- Определение участка по адресу (участок выбирается вручную).
- Расписание выходных и праздничных дней.

## Decisions

- **Интерфейс логики.** `createHomeVisit({ patientName, district, requestedAt, complaints })`, где `requestedAt` — объект `Date`, `complaints` — массив строк. Возвращает один из вариантов:
  - `{ status: 'registered', district, visitDate: 'YYYY-MM-DD' }`;
  - `{ status: 'refused', message: 'Вызовите скорую помощь: 103' }`;
  - `{ status: 'invalid', errors: [...] }`.
- **Красные флаги** — константа `RED_FLAGS` в `src/home-visit.js`; список закрытый, берётся из задачи без дополнений.
- **Время заявки** берётся из поля `datetime-local` формы и трактуется как местное время Сургута: к значению поля добавляется `+05:00`. Расчёт даты визита ведётся в поясе UTC+5, а не в поясе компьютера.
- **Фиксированное смещение вместо `Intl`.** Сургут (Asia/Yekaterinburg) не переходит на летнее время с 2014 года, поэтому смещение +5 часов достаточно. Для нескольких регионов понадобится `Intl.DateTimeFormat` с `timeZone`.

## Risks / Trade-offs

- Список жалоб фиксирован в коде: для изменения нужна новая версия модуля. Для учебного проекта это приемлемо.
